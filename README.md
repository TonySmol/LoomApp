# LoomApp Self-Hosted AI-assisted development
Это самособирающийся (self‑rebuilding) микро‑фреймворк LoomApp, написанный на чистом JavaScript и предназначенный для работы в браузере как IDE/рантайм для модульных приложений. Ниже — детальный разбор архитектуры, ключевых механизмов и потенциальных нюансов.

1. Общая концепция
LoomApp — это single‑file среда, содержащая:

метаданные (LOOM_META, LOOM_GUIDE),

CSS‑темы,

модульные «капсулы» (манифест + контракт + код),

бутлоадер, который всё это оживляет.

Капсулы разбиты на типы: core, build, ui, app и загружаются в порядке, заданном в meta.conventions.loadOrder. После загрузки бутлоадер компилирует модули в топологическом порядке и либо запускает IDE (профиль ide), либо конкретное приложение (профиль app).

2. Архитектура модулей
Каждая капсула (заключена в HTML‑комментарии <!-- LOOM:BEGIN_MODULE --> ... LOOM:END_MODULE -->) содержит три <script>‑блока:

data-role="manifest" – JSON с именем, типом, версией, зависимостями и списком экспортов.

data-role="contract" – формальное описание API (аргументы, возвращаемые типы).

data-role="code" – тело модуля, функция Module(ctx), возвращающая объект экспорта.

Это позволяет статически анализировать код, проверять контракты и собирать приложение «на лету».

2.1. Глобальный контекст
Бутлоадер формирует общий объект ctx с полями:

meta, guide

log, bus, store (подставляются автоматически после компиляции соответствующих Core‑модулей)

require(name) – получение экспорта другого модуля

modules.* – API для управления модулями во время выполнения (list, exists, add, remove, setDef)

Модули не имеют прямого доступа к DOM‑дереву или друг другу, кроме как через ctx.require. Это дисциплинирует зависимости.

3. Ключевые модули и их роли
Ядро (Core)
Core.Logger – многоуровневое логирование (debug/info/warn/error), с историей.

Core.Bus – событийная шина (on/off/emit).

Core.Store – хранилище ключ-значение с персистентностью в localStorage и реакцией на внешние изменения.

Core.Render – утилиты для производительного рендеринга списков (schedule с requestIdleCallback, renderList, updateFraction).

Core.I18n – интернационализация (подстановки, смена языка, загрузка словарей).

Сборка (Build)
Build.Serializer – сборка HTML‑страницы из текущего DOM (extract → generate → download), а также exportJSON и build с профилями (app-only).

Build.Health – проверка целостности: существование обязательных модулей, соответствие версий загрузчика, компилируемость, уникальность имён, экспорты, буквальные ctx.require в коде.

Build.Import – импорт модулей из JSON‑файла.

Build.Patcher – система патчей (JSON Patch + text‑replace) с guards, dry‑run и защитой бутлоадера.

Build.Describe – сбор «чертежа» (blueprint): сигналы, точки расширения, анкоры для вставок.

UI (пользовательский интерфейс IDE)
UI.Shell – центральная панель IDE: список модулей (виртуализированный), редактор манифеста/контракта/кода, сохранение, валидация.

UI.Topbar – верхняя панель с кнопками.

UI.Actions – связывание кнопок Topbar с действиями (здоровье, импорт/экспорт, сборка, командная палитра).

UI.BuildConfig – окно конфигурации сборки: выбор профиля, entry‑app, версий.

UI.CommandPalette – командная строка с регистрируемыми действиями.

UI.Modal / UI.Toast – модальные окна и всплывающие уведомления.

UI.Theme – тёмная/светлая тема, управление CSS‑переменными.

UI.Layout – адаптивная вёрстка (off‑canvas сайдбар на мобильных).

UI.AppSwitcher – переключение между IDE и отдельным приложением.

UI.LanguageSwitcher – переключение языка (RU/EN), с немедленной подстановкой переводов.

UI.Blueprint – интеграция чертежа в UI.

Приложения (App)
App.Host – контейнер для app‑режима (монтирует #app-root, управляет CSS‑классом show-app).

App.Welcome – инициализатор, который выводит приветствие.

4. Процесс сборки (Build.Serializer.build)
Ключевая возможность — сборка app‑only профиля.

Извлекаются все модули из DOM.

Если профиль app, то по entry‑app строится транзитивное замыкание зависимостей, опционально добавляются App.Host и выбранные UI‑хелперы (Modal, Toast, Theme).

Генерируется новый HTML, содержащий только отфильтрованные модули.

В мета‑данных проставляется runProfile: "app" и entryApp.

При запуске такого HTML бутлоадер сразу вызывает mountApp(entryApp).

5. Система патчей (Build.Patcher)
Позволяет программно менять приложение без пересборки:

Формат loom.patch/1: список изменений (цель, метод) + guards (версии).

Поддерживаемые методы: json‑patch (для meta/guide/манифеста/контракта), text‑replace (css/boot/код модуля), module‑add/remove/rename.

Есть проверка на повторное применение (по id) и флаг allowBootPatch.

После патча опционально запускается Health и rebuild.

6. Интернационализация
Модуль Core.I18n + UI.LanguageSwitcher:

Словари добавляются в рантайме (addDict).

Все строки в UI получены через tr(key, fallback), поэтому переключение языка мгновенно обновляет подписи, статус‑бары, меню.

Поддержка параметров ({m}).
